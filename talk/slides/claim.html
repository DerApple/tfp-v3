git push is a compare-and-swap

StepAgent AAgent B
1Sets status and owner, commitsSame task, same edit, commits
2Pushes first: acceptedPush rejected: not a fast-forward
3CLAIMED, starts workRolls back, sees owner A
4LOST RACE, back to next

The remote ref is the lock. No lock server, no clock sync: whoever moves main first wins, and the loser finds out from git itself.

How do you get atomic claims without a server? A claim is a commit that flips the task from todo to in_progress, and then a push. Git only accepts a push that fast-forwards the branch, so if two agents race, exactly one push is accepted. The other gets a rejection, rolls back its claim and is told who won. That's optimistic concurrency, a compare-and-swap on the main ref, and it's the same trick other people building agent teams have converged on.
