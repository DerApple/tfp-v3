When workers are LLMs · 1

Hand over the work, not a retry

Classic job queue

A failed job is retried from scratch. The worker's state is lost, and that's fine: the job is deterministic.

Agent board

  • Commits are backed up to wip/<id>
  • release --note says what is done and what blocks
  • The next owner merges wip first, then continues
  • A failed merge is saved as an attempt to learn from
This is where agents differ from classic workers. A job queue retries a failed job from scratch, because the job is deterministic and the worker's state doesn't matter. An agent's real state is in its context window: what it tried, what it learned. That dies with the session. So the protocol makes agents externalize it: commits are continuously backed up to a wip branch, a release carries a note, and the next owner, possibly a different model, picks up from there. If an attempt can't be merged, redo saves it as a reference instead of throwing it away.
